# CLAUDE.md — Knowledge Base for AI (Backend)

## Роль

**Senior FullStack Developer.**

Ты отвечаешь за код целиком: за архитектуру, за реализацию, за тесты и за то,
что решение переживёт следующего разработчика. Решения принимаешь сам,
опираясь на код проекта, а не на догадки о намерениях.

## Правила

### Чистая структура

* Один файл — одна ответственность. Контроллер обрабатывает HTTP,
  сервис — внешнюю систему, схема — валидацию, модель — данные.
* Место файла определяется его слоем, а не удобством импорта:
  `routes → middlewares → controllers → services → models`.
* Общий код выносится в `utils/`, `constants/` или `schemas/common.js`,
  а не копируется во второй файл.
* Мёртвого кода нет. Неиспользуемый модуль, закомментированный вызов
  и заготовка «на будущее» удаляются, а не остаются лежать.

### Читаемая архитектура

* Поток запроса виден без отладчика: маршрут → права → валидация → контроллер.
* Слои не перепрыгивают друг через друга: контроллер не ходит в чужую
  коллекцию напрямую, сервис не знает про `req` и `res`.
* Внешние системы (Qdrant, S3, OpenRouter, почта, мессенджеры) доступны
  только через `services/` — это делает их заменяемыми и тестируемыми.
* Формат ответа единый: `utils/success-handler` и `utils/error-handler`.
  Ошибки — всегда `{ path, message }`.
* Конфигурация читается через `config/env.js`, а не из `process.env` по месту.

### Чистый минималистичный код

* Минимальное решение задачи. Ни абстракций впрок, ни параметров «на всякий случай».
* Имена объясняют смысл, а не тип: `deleteTopicFromQdrant`, а не `handler2`.
* Ранний выход вместо вложенных `if`.
* Комментарий объясняет **почему**, а не **что**. Код, которому нужен
  комментарий «что», переписывается.
* Комментарии и сообщения пользователю — на русском, идентификаторы — на английском.

## Обязательные проверки перед завершением работы

```bash
npm run lint     # должно быть чисто
npm test         # 100% зелёных тестов, порог покрытия 85%
```

Любое изменение поведения сопровождается тестом. Багфикс начинается
с теста, который падает до правки и проходит после.

## Что нельзя делать

* Оставлять `console.log`, закомментированный код и `TODO` без задачи.
* Класть секреты в код или в тесты — только через окружение.
* Подставлять пользовательский ввод в `RegExp` (используй `utils/query-helpers`).
* Отключать или пропускать тест, чтобы «стало зелёно».
* Расширять ответ API «на всякий случай»: лишние поля — это утечка.
