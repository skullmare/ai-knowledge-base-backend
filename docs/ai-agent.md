# ИИ-агент

## Конвейер ответа

`src/services/agent/index.js` — единственная точка входа. Один и тот же код
обслуживает Telegram и MAX.

```
processMessage(agentUser, text)
  1. история      последние 10 сообщений диалога из MongoDB
  2. rewrite      LLM превращает «а сколько дней?» в самодостаточный запрос
  3. embedding    вектор переформулированного запроса
  4. search       Qdrant, топ-5, фильтр по роли пользователя
  5. сохранение   вопрос пользователя в историю
  6. respond      LLM отвечает по найденному контексту
  7. сохранение   ответ в историю
```

### Почему переформулировка

Пользователь пишет короткими репликами: «а сколько дней?». Вектор такого
текста не найдёт ничего. Первый вызов LLM разворачивает его в
«количество дней отпуска» с опорой на последние 5 сообщений диалога.

Если переформулировка упала — используется исходный текст: деградация
качества поиска приемлема, отказ в ответе нет. Ошибки эмбеддингов и поиска,
напротив, пробрасываются: без контекста агент начнёт выдумывать.

### Порядок записи в историю

Вопрос сохраняется **после** успешного поиска, но **до** генерации ответа.
Если упадёт эмбеддинг или Qdrant, история не засорится вопросом, на который
ответа не будет. Если упадёт генерация — вопрос останется, и следующая
попытка получит контекст.

### Изоляция по ролям

Фильтр `metadata.accessibleByRoles = <роль пользователя>` применяется
на стороне Qdrant, внутри поискового запроса, а не после получения выдачи.
Чанк недоступной темы физически не попадает в ответ и не попадает в промпт.

### Промпт

```
Ты ИИ-агент корпоративной базы знаний. Отвечай строго на основе контекста.
Если ответа нет — скажи об этом честно.

Контекст:
[1] <чанк>
[2] <чанк>

<правила оформления ссылок>
```

Если контекст пуст, промпт прямо сообщает об этом — так модель отвечает
«не нашёл», а не сочиняет. Правила оформления ссылок идут после контекста,
иначе модель принимает их за часть данных.

## Пользователи агента

`AgentUser` создаётся только из мессенджера, через API его создать нельзя.

```
регистрация: пользователь делится контактом
  → телефон нормализуется к виду +<цифры>
  → поиск существующей записи по chat id ИЛИ по любому варианту телефона
  → created  — новая запись, статус pending, роли нет
  → linked   — найдена по телефону, привязан второй мессенджер
  → existing — уже зарегистрирован
  → invalid  — телефон определить не удалось
```

Поиск по нескольким вариантам телефона (`79991234567`, `+79991234567`, исходная
строка) нужен потому, что Telegram и MAX отдают номер по-разному, а записи,
созданные до нормализации, остались в старом формате. Один человек с двумя
мессенджерами — одна запись `AgentUser`.

Гонка двух сообщений подряд обрабатывается явно: при ошибке дубликата ключа
(`11000`) выполняется повторный поиск и возвращается найденная запись.

## Выдача доступа

Новый пользователь получает `status: pending` и не имеет роли — агент ему
не отвечает. Администратор назначает роль через `PATCH /agent/users/:id`:
статус автоматически становится `active`, и пользователю уходит уведомление
в привязанные мессенджеры.

Уведомление — побочный эффект: недоступность Telegram или MAX не должна
проваливать запрос администратора, поэтому ошибки отправки только логируются.

## Обработчики мессенджеров

`telegram/handlers.js` и `max/handlers.js` устроены одинаково:

```
нет записи        → просьба поделиться контактом
статус blocked    → сообщение о блокировке
нет роли          → сообщение об ожидании доступа
иначе             → lastActivity, счётчик запросов, индикатор набора,
                    processMessage, ответ
```

Оба обработчика получают бота параметром, а не берут из глобального состояния
модуля: так они тестируются без запуска бота и не падают, если бот
не инициализирован.

## Транспорт

* **Telegram** — библиотека `node-telegram-bot-api` в режиме polling.
* **MAX** — собственный HTTP-клиент (`config/max.js`) поверх Bot API:
  long polling с маркером последнего обновления, пауза 1 секунда при пустой
  выдаче, обработка `429` с учётом `Retry-After`.

Оба бота не запускаются, если не задан токен — приложение при этом
работает нормально, просто без соответствующего канала.
