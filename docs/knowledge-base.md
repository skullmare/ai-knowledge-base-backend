# База знаний

## Тема

Тема — единица знания: markdown-документ с категорией и списком ролей агента,
которым он доступен.

| Поле | Назначение |
| --- | --- |
| `name` | Заголовок, участвует в полнотекстовом поиске |
| `markdownContent` | Содержимое (`select: false` — не отдаётся в списках) |
| `collaborationData` | Бинарное состояние Yjs (`select: false`) |
| `status` | `review` \| `approved` \| `archived` |
| `metadata.category` | Ссылка на `TopicCategory`, обязательна |
| `metadata.accessibleByRoles` | Роли агента, минимум одна |
| `vectorData.isIndexed` | Соответствует ли содержимое тому, что лежит в Qdrant |
| `createdBy` / `updatedBy` | Авторство |

Существование категории и ролей проверяется дважды: в zod-схеме (даёт понятный
`400`) и валидатором модели (защищает от записи в обход API).

## Жизненный цикл

```
      создание
         │
         ▼
    ┌─────────┐   POST /:id/approve    ┌──────────┐
    │ review  │ ─────────────────────▶ │ approved │
    └─────────┘                        └──────────┘
         ▲                                   │
         │      любая правка (PATCH или WS)  │
         └───────────────────────────────────┘
         │
         │ PATCH { status: 'archived' }
         ▼
    ┌──────────┐
    │ archived │
    └──────────┘
```

Правила, которые держат индекс в согласованном состоянии:

* **`approved` нельзя выставить через `PATCH`.** Схема принимает только
  `review` и `archived`. Единственный путь в `approved` — `/approve`,
  где происходит индексация.
* **Любая правка удаляет чанки из Qdrant и снимает `isIndexed`.** Иначе агент
  продолжал бы отвечать по устаревшему тексту, которого уже нет в теме.
* **Пустую тему нельзя одобрить** — `422`. Индексировать нечего, а пустой набор
  чанков ломает нарезку.
* **Повторное одобрение** — `409`.
* **Статус меняется только после успешной индексации.** Если Qdrant недоступен,
  тема остаётся в `review`, и повторное одобрение возможно.

## Совместное редактирование

Содержимое правится не через REST, а через WebSocket-сервер Hocuspocus
(`src/services/collaboration.mjs`), подключённый к `/api/v1/collaboration`.

```
onAuthenticate   проверка accessToken → пользователь жив, не заблокирован,
                 есть topics.read; connection.readOnly = !topics.update
onLoadDocument   чтение collaborationData темы и применение к Y.Doc
onStoreDocument  (debounce 3 с) сохранение состояния Yjs + markdown,
                 статус → review, isIndexed → false, updatedBy
onDisconnect     запись в лог
```

Ключевые моменты:

* **`connection.readOnly` действительно ограничивает запись.** Раньше право
  `topics.update` только вычислялось, но не применялось, и пользователь с одним
  `topics.read` мог править документ.
* **Markdown пересчитывается на сервере** из Y.Doc через `@blocknote/server-util`,
  а не присылается клиентом. Клиент не может подсунуть текст, отличный от того,
  что видят соавторы.
* **Сохранение с задержкой 3 секунды** — компромисс между потерей данных
  при обрыве и нагрузкой на БД.
* **Правка снимает индексацию** ровно так же, как REST-правка.

Модуль написан как ESM (зависимости Hocuspocus и BlockNote поставляются только
в этом формате) и подключается из CommonJS через динамический `import()`
в `services/init-collaboration.js`.

## Индексация в Qdrant

```
syncTopicToQdrant(topic)
  1. удалить прежние чанки темы (фильтр metadata.topicId)
  2. собрать текст: "# <name>\n\n<markdownContent>"
  3. нарезать MarkdownTextSplitter (800 символов, перекрытие 80)
  4. получить эмбеддинги пачкой
  5. upsert точек с payload
```

Payload каждой точки:

```jsonc
{
  "text": "текст чанка",
  "metadata": {
    "topicId": "...",              // по нему удаляются чанки темы
    "name": "название темы",
    "category": "...",
    "accessibleByRoles": ["...", "..."]   // по нему фильтруется поиск
  }
}
```

Заголовок темы добавляется в начало текста перед нарезкой — так первый чанк
несёт контекст, а не начинается с середины мысли.

Удаление старых чанков **до** загрузки новых, а не после, чтобы при падении
на середине в базе не оказалось двух версий одной темы.

## Категории

`TopicCategory` — плоский справочник с уникальным именем. Категорию нельзя
удалить, пока на неё ссылается хотя бы одна тема: проверка в схеме валидации,
и для одиночного, и для пакетного удаления.

## Поиск

Список тем ищет по текстовому индексу MongoDB (`name` + `markdownContent`)
и сортирует по релевантности `textScore`. Поиск по остальным справочникам —
регулярное выражение с экранированием спецсимволов (`utils/query-helpers`),
чтобы ввод вида `.*` не выбирал всю таблицу и не приводил к ReDoS.
