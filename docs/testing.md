# Тестирование

```bash
npm test                  # весь набор
npm test -- --coverage    # с отчётом о покрытии
npm run test:watch        # режим наблюдения
```

Текущее состояние: **375 тестов, 25 наборов, ~91 % покрытия операторов**
при пороге 85 %.

## Устройство

| Файл | Роль |
| --- | --- |
| `tests/global-setup.js` | поднимает in-memory MongoDB один раз на весь прогон |
| `tests/global-teardown.js` | останавливает её после прогона |
| `tests/env.js` | переменные окружения до первого `require` приложения |
| `tests/setup.js` | подключение к БД, моки внешних систем, очистка данных после каждого теста |
| `tests/helpers/mocks.js` | заглушки почты, S3, Qdrant, LLM и ботов |
| `tests/helpers/factories.js` | фабрики сущностей с уникальными значениями |
| `tests/helpers/request.js` | приложение, supertest, авторизованные запросы |

Тесты идут **строго последовательно** (`maxWorkers: 1`): все наборы работают
с одной базой и чистят её после каждого теста. При параллельном запуске
`afterEach` одного файла удалял бы данные другого прямо посреди запроса.

## Что мокается

Внешние системы — почта, S3, Qdrant, OpenRouter, Telegram, MAX, сервер
совместного редактирования. Они медленные, платные и недоступны в CI.

MongoDB **не** мокается: тесты работают с настоящей базой в памяти, поэтому
проверяются реальные индексы, валидаторы схем, текстовый поиск и уникальность.

S3-клиент — особый случай: `getSignedUrl` подписывает запрос настоящим
клиентом, поэтому мокается только сетевой вызов `send`, а конфигурация
и подпись остаются реальными.

## Структура тестов

### `tests/unit/`

| Файл | Покрывает |
| --- | --- |
| `utils.test.js` | обработчики ответов, пароли, хелперы запросов, журнал, справочники |
| `middlewares.test.js` | auth, permission, validate, rateLimit |
| `models.test.js` | валидаторы схем, индексы, `select: false` |
| `services.test.js` | JWT, регистрация пользователя агента, нарезка, Qdrant, S3 |
| `agent.test.js` | конвейер ответа ИИ-агента |
| `messengers.test.js` | обработчики Telegram и MAX, уведомления |
| `init.test.js` | сиды, синхронизация индексов, инициализация Qdrant, env |
| `email.test.js` | отправка писем и шаблоны |
| `config.test.js` | клиенты MongoDB, Telegram, MAX, Qdrant |
| `integrations.test.js` | адаптеры OpenRouter, запуск ботов, загрузка Hocuspocus |

### `tests/integration/`

По одному файлу на ресурс: `auth`, `password`, `profile`, `platform-user`,
`platform-role`, `agent-role`, `agent-user`, `topic`, `topic-category`, `log`,
`file`, `reference`, `app`, `collaboration-ws`, `health`.

Каждый ресурс проверяется по одному чек-листу:

1. **успешный сценарий** — код ответа, форма данных, побочные эффекты в БД;
2. **валидация** — обязательные поля, форматы, границы;
3. **предусловия** — несуществующие связи, дубликаты, занятые сущности;
4. **права** — отказ пользователю без нужного права;
5. **авторизация** — отказ без токена;
6. **отказ внешней системы** — что видит пользователь, что остаётся в БД.

## Как писать тест

```js
const { app, request, createAuthenticatedUser, authRequest } = require('../helpers/request');

it('создаёт тему в статусе review', async () => {
    const { token } = await createAuthenticatedUser();          // роль со всеми правами
    // const { token } = await createAuthenticatedUser({ permissions: ['topics.read'] });

    const response = await authRequest(token).post('/api/v1/topics').send(payload);

    expect(response.status).toBe(201);
    expect(response.body.data.status).toBe('review');
});
```

Правила:

* Название теста описывает **поведение системы**, а не имя функции.
* Проверяется наблюдаемый результат: код ответа, тело, состояние БД, вызовы
  моков — не внутренние переменные.
* Тест не зависит от порядка выполнения: всё нужное создаётся внутри него.
* Фабрики генерируют уникальные логины, email и телефоны — уникальные
  индексы не конфликтуют между тестами.

## Багфикс начинается с теста

Порядок обязателен: сначала тест, воспроизводящий ошибку и падающий на текущем
коде, затем правка. Так проверяется, что тест действительно ловит проблему.

Несколько ошибок в этом проекте нашли именно тесты, а не чтение кода:
дубликат кода события `PROFILE_ERROR`, строковые значения в пагинации из-за
поведения `.default()` в zod v4, пути ошибок вида `login.login`.
