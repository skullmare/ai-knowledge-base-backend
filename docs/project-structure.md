## Слои и их правила

### `config/`

Единственное место, где читается `process.env`, и единственное, где создаются
клиенты внешних систем.

`env.js` отдаёт значения через геттеры — это важно для тестов, которые меняют
окружение на лету. `assertRequiredEnv()` роняет процесс на старте в проде,
если не заданы `MONGODB_URI`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`.

Клиент Qdrant создаётся **лениво**, при первом обращении: подключение к
внешней базе не должно быть побочным эффектом `require`.

### `routes/`

Только описание маршрута. Никакой логики. Порядок middleware фиксирован:

```js
router.patch('/:id',
    auth,                             // кто
    checkPermission('topics.update'), // можно ли
    validate(patchTopicSchema),       // корректны ли данные
    topicsController.updateTopic      // что делать
);
```

Маршруты с конкретным путём объявляются **до** параметрических,
иначе `/delete/many` попадёт в обработчик `/:id`.

### `middlewares/`

* `auth` — проверяет Bearer-токен, существование и статус пользователя,
  кладёт payload в `req.user`;
* `permission(required)` — читает права роли и сверяет со списком требуемых;
* `validate(schema)` — разбирает `{ userId, body, params, query }` одной zod-схемой,
  кладёт результат в `req.validatedData`, ошибки отдаёт списком `{ path, message }`;
* `rateLimit` — фабрика лимитеров; в тестовом окружении отключается.

### `controllers/`

Один файл — одна операция, `export.js` собирает их в объект. Контроллер:

1. берёт данные **только** из `req.validatedData` (и `req.user.id`);
2. вызывает сервисы;
3. пишет событие в журнал через `utils/log-handler`;
4. отвечает через `success-handler` / `error-handler`.

Контроллер не валидирует данные повторно и не обращается к внешним системам
напрямую.

### `schemas/`

zod-схемы валидируют не только формат, но и предусловия операции: существование
связанных записей, уникальность имени, запрет удаления системной роли,
занятость сущности другими записями. Такая проверка возвращает `400` с точным
`path`, вместо `500` из глубины Mongoose.

Общие кирпичи — в `schemas/common.js`: `objectId`, `dbExists`, `dbAllExist`,
`paginationQuery`.

> Особенность zod v4: `.default()` возвращает значение **в обход** `transform`,
> поэтому дефолт пагинации задаётся числом, а не строкой.

### `services/`

| Каталог | Ответственность |
| --- | --- |
| `agent/` | конвейер ответа ИИ-агента: переформулировка, поиск, генерация |
| `agent-user/` | регистрация пользователя мессенджера и уведомления |
| `qdrant/` | синхронизация и удаление чанков темы |
| `chunker/` | нарезка markdown на чанки |
| `openrouter/` | чат-запросы и эмбеддинги |
| `yandex/S3/` | загрузка, presigned-ссылки, удаление, разбор URL |
| `email/` | отправка писем |
| `telegram/`, `max/` | боты, обработчики сообщений, клавиатуры |
| `collaboration.mjs` | сервер Hocuspocus для совместного редактирования |
| `init-collaboration.js` | CommonJS-обёртка над ESM-модулем совместного редактирования |

В сервисах нет `req` и `res` — поэтому один и тот же сервис вызывается
и из контроллера, и из обработчика сообщения бота.

### `models/`

Схемы Mongoose. Здесь же живут инварианты уровня данных: непустой список прав
у роли, существование категории и ролей у темы, `select: false` для паролей,
токенов и тяжёлого содержимого тем.

### `constants/`

* `permissions.js` — дерево прав, `ALL_PERMISSIONS`, форма для UI;
* `actions.js` — события журнала: код, человекочитаемое имя, сущность, категория;
* `topic-populate.js` — единый набор `populate` для всех чтений темы.

Коды событий и прав уникальны — это проверяется тестом, потому что дубликат
кода молча ломал сопоставление события с категорией.

### `utils/`

`success-handler`, `error-handler`, `log-handler`, `logger`, `password-handler`,
`auth-cookie`, `query-helpers` (экранирование поиска и сборка пагинации),
`templates/` — HTML-шаблоны писем.

## Соглашения

* Файлы и каталоги — `kebab-case`, экспортируемые функции — `camelCase`,
  модели и классы — `PascalCase`.
* Один файл — одна операция или одна сущность.
* Тексты сообщений пользователю — на русском.
* Комментарий объясняет причину решения, а не пересказывает код.
