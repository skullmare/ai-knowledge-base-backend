# HTTP API

Базовый префикс — `/api/v1`.

## Формат ответа

Успех:

```json
{
  "success": true,
  "message": "Список тем успешно получен",
  "data": [],
  "pagination": { "total": 0, "current": 1, "limit": 10, "pages": 0 }
}
```

`pagination` присутствует только у списочных ручек.

Ошибка:

```json
{
  "success": false,
  "message": "Ошибка валидации",
  "errors": [{ "path": "metadata.category", "message": "Категория не найдена" }]
}
```

`path` указывает на поле запроса, чтобы фронтенд подсветил конкретный ввод.

## Коды ответов

| Код | Когда |
| --- | --- |
| 200 | Успешная операция |
| 201 | Ресурс создан |
| 400 | Ошибка валидации или нарушение предусловия операции |
| 401 | Нет токена, токен невалиден, неверные учётные данные |
| 403 | Аккаунт заблокирован или не хватает прав |
| 404 | Ресурс или маршрут не найден |
| 409 | Конфликт состояния (например, повторное одобрение темы) |
| 413 | Тело запроса больше 1 МБ |
| 422 | Операция невозможна для текущего состояния ресурса |
| 429 | Превышен лимит запросов |
| 500 | Внутренняя ошибка (детали только в логе) |

> Несуществующий `:id` часто даёт `400`, а не `404`: существование записи
> проверяется схемой валидации, до контроллера. Это осознанный компромисс —
> одно место проверки вместо дублирования в каждом контроллере.

## Маршруты

### Служебные

| Метод | Путь | Права | Описание |
| --- | --- | --- | --- |
| GET | `/health` | — | Статус, uptime, время сервера |
| GET | `/permissions` | — | Справочник прав для интерфейса |
| GET | `/actions` | — | Справочник событий журнала |

### Аутентификация — `/auth`

| Метод | Путь | Права | Описание |
| --- | --- | --- | --- |
| POST | `/login` | — | Проверка пароля и отправка кода 2FA на почту |
| POST | `/verify-2fa` | — | Проверка кода, выдача `accessToken` и refresh-cookie |
| POST | `/refresh` | cookie | Обновление пары токенов |
| POST | `/logout` | — | Сброс refresh-cookie |

Лимиты: `login` и `verify-2fa` — 10 запросов / 15 мин, `refresh` — 60 / 15 мин.

### Профиль — `/profile`

| Метод | Путь | Права | Описание |
| --- | --- | --- | --- |
| GET | `/` | авторизация | Свой профиль с раскрытой ролью |
| PATCH | `/update` | авторизация | Имя, фамилия, логин, email, аватар |

При смене аватара прежний файл удаляется из S3.

### Пароль — `/password`

| Метод | Путь | Права | Описание |
| --- | --- | --- | --- |
| PUT | `/change` | авторизация | Смена пароля по текущему |
| POST | `/forgot` | — | Письмо со ссылкой восстановления |
| POST | `/reset/:token` | — | Установка нового пароля по токену |

`/forgot` и `/reset` — 5 запросов в час. `/forgot` отвечает одинаково для
существующего и несуществующего адреса.

### Сотрудники — `/users`

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/` | `platformUsers.read` |
| GET | `/:id` | `platformUsers.read` |
| POST | `/` | `platformUsers.create` |
| PATCH | `/:id` | `platformUsers.update` |
| DELETE | `/:id` | `platformUsers.delete` |

Фильтры списка: `page`, `limit`, `search`, `role`, `status`.
При создании пароль генерируется сервером и отправляется письмом.
Системного пользователя нельзя удалить, заблокировать или сменить ему роль.

### Роли платформы — `/platform/roles`

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/` | `platformRoles.read` |
| GET | `/:id` | `platformRoles.read` |
| POST | `/` | `platformRoles.create` |
| PATCH | `/:id` | `platformRoles.update` |
| DELETE | `/delete/many` | `platformRoles.delete` |
| DELETE | `/:id` | `platformRoles.delete` |

Системную роль нельзя удалить и нельзя изменить её права. Роль, назначенную
хотя бы одному пользователю, удалить нельзя.

### Роли ИИ-агента — `/agent/roles`

Тот же набор операций, права `agentRoles.*`. Роль нельзя удалить, если она
назначена теме или пользователю агента.

### Пользователи ИИ-агента — `/agent/users`

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/` | `agentUsers.read` |
| GET | `/:id` | `agentUsers.read` |
| PATCH | `/:id` | `agentUsers.update` |
| DELETE | `/:id` | `agentUsers.delete` |

Фильтры: `page`, `limit`, `search`, `role`, `status`, `hasPhone`.
Создание записи происходит только из мессенджера, через API её создать нельзя.
Назначение роли переводит пользователя в `active` и отправляет ему уведомление
в привязанный мессенджер.

### Темы — `/topics`

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/` | `topics.read` |
| GET | `/:id` | `topics.read` |
| POST | `/` | `topics.create` |
| PATCH | `/:id` | `topics.update` |
| POST | `/:id/approve` | `topics.approve` |
| DELETE | `/:id` | `topics.delete` |

Фильтры списка: `page`, `limit`, `search` (полнотекстовый), `category`, `role`, `status`.
Списки не отдают `markdownContent` и `collaborationData`.

### Категории тем — `/topic/categories`

Полный CRUD плюс `DELETE /delete/many`, права `topicCategories.*`.
Категорию, используемую темой, удалить нельзя.

### Файлы — `/files`

| Метод | Путь | Право | Описание |
| --- | --- | --- | --- |
| POST | `/upload` | `files.upload` | Загрузка через сервер, до 10 МБ |
| POST | `/presigned-url` | `files.upload` | Ссылка для прямой загрузки в S3 (15 мин) |
| POST | `/presigned-complete` | `files.upload` | Подтверждение загрузки, выдача публичного URL |

Ключ объекта формирует сервер; `presigned-complete` принимает только ключ вида
`uploads/xx/yy/<uuid>[.ext]`, чтобы нельзя было подтвердить чужой объект в бакете.

### Журнал — `/logs`

| Метод | Путь | Право |
| --- | --- | --- |
| GET | `/` | `logs.read` |
| GET | `/:id` | `logs.read` |

Фильтры: `page`, `limit`, `search`, `action`, `category`, `entityId`, `user`,
`status`, `startDate`, `endDate`.

### Совместное редактирование — WebSocket

`wss://<host>/api/v1/collaboration` — протокол Hocuspocus.
Токен передаётся при подключении, имя документа — идентификатор темы.
Подробности — [knowledge-base.md](./knowledge-base.md).

## CORS и лимиты

* Разрешённые origin задаются переменной `CORS_ORIGINS` (список через запятую).
  Если она не задана, используется список по умолчанию: в разработке —
  `http://localhost:5173` и `:5174`, иначе — домен продакшн-фронтенда.
  Пустым список не бывает: без `Access-Control-Allow-Origin` браузер
  блокирует все запросы фронтенда.
* `credentials: true` — refresh-токен ходит в httpOnly-cookie.
* Максимальный размер тела — 1 МБ (файлы идут отдельным маршрутом, до 10 МБ).
